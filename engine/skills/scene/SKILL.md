# 场景 = 工作区

**核心：一个工作区 = 一类活 + 一份记忆 + 一条常驻上下文。**

不要把所有事塞进一个对话流。用户的股票、开发、写作、运维是**不同的活**，应该有各自的工作区、各自的记忆、各自的上下文。

---

## 开场第一件事：认领身份

**不要假设你知道自己是谁。** 每次会话开始，必须按顺序做这四步：

### 1. 确认当前工作区

看你的工作目录（`pwd`）。工作区的名字通常就是目录名，或者问用户当前在做哪类活。

### 2. 读这个工作区的场景配置

```sh
cat .scene.json 2>/dev/null || echo "（没有场景配置）"
```

如果有，它告诉你：这个场景叫什么、负责什么、不碰什么。

### 3. 读身份卡（如果有）

```sh
cat IDENTITY.md 2>/dev/null
```

这是**工具生成的**，不是手写的。里面写着：项目是什么、当前在做什么、有哪些技能。

### 4. 读交接（如果有）

```sh
node "$DSH_TOOLS/handoff/handoff.mjs" show .
```

告诉你上次做到哪、下一步干什么、卡在哪。

**做完这四步你才知道自己该干什么。** 跳过任何一步都可能串台——回答成了另一个场景的问题。

---

## 为什么要这么麻烦

一位实践者踩过的坑：

> 「不是因为把会话命名成场景名，就自动按场景输出东西。**会话开场第一件事是先认身份**——拿自己的会话 ID 去对场景表，对号入座，然后读定位卡和记忆文件。这不是什么神奇的自启动，**是一条写进每轮必读宪法里的规矩**。」

引擎不会自动给你身份。**必须自己认领。**

---

## 场景的六件套（缺一就会失效）

| # | 组件 | 缺了会怎样 | 我们怎么落地 |
|---|---|---|---|
| 1 | 场景配置 | 不知道这个工作区是干什么的 | `.scene.json` |
| 2 | 定位卡（职责/不碰什么） | 做了不该做的事 | 写进 `.scene.json` 的 `duty` / `avoid` |
| 3 | 场景记忆 | **换会话就断片** | `HANDOFF.md` |
| 4 | 专属技能 | 用通用办法硬干专业活 | `skills/` 里按场景分 |
| 5 | 专属面板 | —— | Swift 侧的工作区列表 |
| 6 | 身份索引 | **会猜，一猜就串台** | 工作区标题 + `.scene.json` |

**2、3、6 不可省。**

---

## `.scene.json` 的格式

放在工作区根目录。最小可用：

```json
{
  "name": "股票盯盘",
  "duty": ["看持仓", "记交易", "复盘"],
  "avoid": ["不碰开发代码", "不动其他工作区的文件"],
  "skill": "stock"
}
```

字段说明：

| 字段 | 作用 |
|---|---|
| `name` | 场景名，和用户看到的标题一致 |
| `duty` | 这个场景负责什么（可执行的动作） |
| `avoid` | **明确不碰什么** —— 这条最重要，边界靠它 |
| `skill` | 对应的专属技能名 |

## 什么时候该开新场景

**开**：
- 这类活会反复回来（不是一次性）
- 有自己的资产目录
- 能说清它**不碰什么**

**不开**：
- 一次性的活
- 只是现有场景里的一个功能
- **说不清边界的，先别开**

判据：**「三天后我还会为它单独打开一个工作区吗？」**

---

## 不要做的事

| ❌ | 为什么 |
|---|---|
| 用「我记得我们在做 X」判断身份 | 记错就串台。要读文件确认 |
| 把场景记忆堆成一本流水账 | 超 4KB 就没人读了 |
| 一个工作区里干两件不相关的事 | 上下文互挤、记忆互串 |
| 替用户决定该开几个场景 | 边界是用户的事 |

---

## 和别的技能怎么配合

- `handoff` —— 场景记忆的具体写法（§〇 交接 ≤4KB）
- `identity`（在 handoff 里）—— 生成身份卡
- `cost-guard` —— 轮次超线时该换会话
- `workbench-discipline` —— 多项目防污染的上位规则
