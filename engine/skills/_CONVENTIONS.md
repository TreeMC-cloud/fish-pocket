# 工具的统一约定

文件来源：用户 2026-11-08：「所有都需要自动触发啊，傻瓜式的，不要让我一直配置」+ 移植自 luanyujia-workbench 二-标准化规范 §6.3

> 所有 `engine/skills/*/` 下的可执行工具都遵守这一套。新增工具前先读这里。

---

## 一、默认空跑，`--go` 才真干

**任何会改文件、发请求、删东西的操作，默认只打印"将要做什么"，加 `--go` 才真执行。**

| 命令 | 行为 |
|---|---|
| `node xxx.mjs` | 打印计划，不动任何文件 |
| `node xxx.mjs --go` | 真执行 |

**为什么**：Agent 会看错上下文。它以为在清理临时文件，实际可能删了源码。默认空跑让「看一眼再决定」成为默认路径。

**真实例子**（他自己的话）：

> 「换会话.mjs `<面板id>` —— **空跑：打印计划、交接文件与新旧程度，不动任何东西**
> 换会话.mjs `<面板id>` `--go` —— **真换：上面四步全做**」

---

## 二、退出码三态

| 码 | 含义 |
|---|---|
| `0` | 没问题 / 操作成功 |
| `1` | 有问题（检查发现违规、操作失败但没崩） |
| `2` | 用法错误（参数写错、路径不存在） |

**这条最重要**：如果所有情况都返回 0，那就不是检查，是装饰。

---

## 三、检查必须能失败

写检查工具时**必须造一个反例证明它会报错**。

```
判据：把明显的坏数据喂给它，看退出码是不是变 1。
      不会失败的检查 = 假检查。
```

他自己踩过这个坑：

> 「体检因此一直报『8 个技能 front-matter 多了字段』」——检查器自己写错，报了一年的假阳性。

---

## 四、输出给数字和差异，不给形容词

| ❌ | ✅ |
|---|---|
| 交接文件不合格 | 缺小节「4) 下一步 / 卡点」；体量 5.2 KB 超 4 KB 红线 |
| 有问题 | 3 个临时残留：app.mjs.bak, test.tmp, 副本.json |
| 内存不足 | 可用 168 MB / 4194 MB（4%，低于 15% 红线） |

---

## 五、注释写「为什么」，不写「做什么」

```js
// ❌ 没用
// 检查文件是否存在
if (fs.existsSync(f)) ...

// ✅ 有价值
// iSH 上 free -m 是静态桩（连续 5 次都返回 4096/0/4096），
// 拿它判"内存充足"会让哨兵在最该拦的时候放行，比没有判据更危险。
```

---

## 六、不许无参就跑危险操作

**没有参数时只打印用法，exit 2。**

真实教训：`identity.mjs` 原来无参就写 `IDENTITY.md`，`fetch-index.mjs` 无参就发起几十次网络请求。都改掉了。

---

## 七、路径要用环境变量拼，不写死

| 变量 | 指向 |
|---|---|
| `DSH_TOOLS` | 技能根目录（`/opt/dsh/nodejs-project/skills`） |
| `DSH_HOME` | 引擎 home（`$DSH_IOS_DATA/../dsh`） |
| `DSH_IOS_DATA` | App 数据目录 |
| `DSH_TURNS_FILE` | 轮次记账文件 |
| `DSH_SENTINEL_LEDGER` | 派单台账 |

**为什么**：技能目录是只读的 app bundle，工作目录是可写的 workspace，两者不在同一路径下。写死相对路径必然找不到。

---

## 八、测试在 /tmp 里做，跑完删干净

```sh
D=$(mktemp -d)          # 不要写死 /tmp/xxx（可能撞车或建不了）
# ... 测试 ...
rm -rf "$D"
```

**注意**：iSH 上 `/tmp` 某些名字可能建不了（试过 `/tmp/audit` 失败），用 `mktemp -d` 拿随机名。

---

## 九、修改权五档

**动手前先问一句：这份文件属于哪一档？**

| 档 | 内容 | 谁能改 |
|---|---|---|
| **A 共享 · 宪法** | `engine/AGENTS.md` 的铁律段、`_CONVENTIONS.md`、`docs/场景地盘与仲裁.md` | **只有用户明确要求时**才能改；改完要在通知板公告 |
| **B 共享 · 板与台账** | `shared.mjs` 的待办板 / 通知板 | 任何场景按规矩写，⛔ **不许删改别人的行** |
| **C 共享 · 工具与运行时** | `engine/skills/*/*.mjs` 的公共逻辑、`engine/plugins/` | 改前确认没有别的场景正在用；改完跑 selfcheck |
| **D 专属** | 自己 `.scene.json` 里 `territory` 声明的路径 | 自由改。但改「规矩类」内容（铁律/必须/禁止/判据/阈值）要告知 |
| **E 别人的专属** | 别人 territory 里的东西 | ⛔ **一个字不许写，只能提请求** |

### 为什么要有这一档

真实事故（他的原话）：

> 「`<客户>助手1` 与自己助手互相往对方地盘写，内容互相覆盖污染 —— **专区只让一个人进门**」

### 提请求而不是硬改

```sh
node "$DSH_TOOLS/shared/shared.mjs" notice "请求：改 docs/XX，理由 YY" --go
```

对方看到后决定做不做。**不要直接动手。**

### 判据（怎么知道自己在越界）

```
1. 这个路径在我的 .scene.json 的 territory 里吗？
   在 → D 档，可以改
   不在 → 继续看

2. 这个文件在 _CONVENTIONS.md 的 A 档列表里吗？
   在 → 必须用户明确要求

3. 这个文件在别人的 territory 里吗？
   在 → E 档，只能提请求

4. 都不是 → 先登记再动手（见第七条）
```
