# 交接 —— 记忆在文件里，不在会话里

**iOS 上的会话随时会没。** 内存紧张时系统会杀掉 App，用户换个话题会开新会话，上下文超限会被压缩。凡是没有落到文件里的进度，都不存在。

核心只有一句：**会话可以无限换，活不能断。**

---

## 什么时候读

- 接到一个**多步骤**任务的开头 —— 先看有没有上一轮的交接
- 用户说「继续」「接着做」「上次那个」—— **必须先读**，不要凭印象猜
- 自己感觉上下文快满了 —— 先把交接写完再继续

## 什么时候写

- 一个阶段做完、准备停手
- 上下文快到压缩线（**在压缩之前写，不要等报错**）
- 用户说「先这样」「下次再说」
- 交出去一个子任务、等对方结果（写清"在等什么"）

---

## 交接文件写在哪

工作目录下的 `HANDOFF.md`。一个项目一份，覆盖写，不追加。

**为什么覆盖不追加**：追加会无限变长，最后没人读。「上次进度」只有一份是有意义的，历史属于归档不属于入口。

---

## 固定五小节（≤4 KB，超了就说明你在写周报）

```markdown
# 交接

## 1) 上次交接
- 做了什么 / 结果 / 证据（证据是路径、命令输出、链接，不是"已完成"）

## 2) 当前项目
| 项目 | 状态 | 下一步 |
|---|---|---|
| <名字> | 进行中 | <具体动作，不要写"继续开发"> |

## 3) 变更记录
- <日期>：<改了什么 + 为什么>

## 4) 下一步 / 卡点
- 下一步：<谁先动，按什么顺序>
- 卡点：<没有就写"无"；有就写清在等什么、等谁>

## 5) 关键文件位置
- <路径> — <这是什么>
```

**最常见的错误**：把交接写成周报（今天做了 1、2、3、4、5 件事，每件三大段）。结果一是超线，二是新会话读完了**仍然不知道下一步该干什么**。

> **交接只回答四个问题：我是谁 / 干到哪 / 下一步 / 卡在哪。**

---

## 该记什么，不该记什么

| ✅ 记 | ⛔ 不记 |
|---|---|
| 建/改了哪个文件、修了什么 bug | 搜索结果 |
| 选定了什么方案、为什么 | 临时文件路径 |
| 用户明确表达的偏好和约定 | 报错原文（记「症状 → 根因」） |
| 卡在哪、在等什么 | 聊天过程 |

**每次写回 ≤10 行。**

判据：**「三天后我还会需要这一行吗？」** 不需要就别写。

---

## 身份卡：让「我是谁」不用每次读

交接文件记**进度**，身份卡记**身份**。两个都要有，但来源不同：

| | `HANDOFF.md` | `IDENTITY.md` |
|---|---|---|
| 谁写 | 人（或 Agent 自己） | **工具生成** |
| 记什么 | 下一步 / 卡点 / 变更 | 职责 / 能力 / 边界 |
| 能不能手改 | 能 | **不能**，下次生成会覆盖 |

```sh
node "$DSH_TOOLS/handoff/identity.mjs"          # 生成/刷新
node "$DSH_TOOLS/handoff/identity.mjs" --show   # 只看不写
```

**为什么值得做**：把「我是谁」从"开场要读一堆文档"变成"出场就知道"。

> 这是从别人踩坑里学来的一条：手写的身份文档会越写越多，最后没人读；工具生成的能保证每次都是当前真实情况。

## 换会话前跑一道闸门

单独跑 `turns.mjs` 和 `handoff.mjs` 容易漏一个。`preflight.sh` 按固定顺序跑完三个检查：

```sh
sh "$DSH_TOOLS/handoff/preflight.sh" <工作目录>
```

退出码 `0` = 可以换，`1` = 不能换。

**它挡的是最危险的一种组合**：轮次超线了必须换会话，但交接没写——这时候换，进度直接丢，而且没人会发现（新会话读不到交接，会当成全新任务）。

输出会说清哪一条没过，以及该怎么修。

## 写完自检

写完后问自己一句：

> **一个全新的人（或全新的会话）读完这份交接，30 秒内能不能说出「下一步干什么」？**

答不上来，说明这份交接没写好 —— 要么"下一步"太虚（「继续开发」），要么关键信息没落盘。

---

## 和 todo 的分工

- **todo** 管「这一轮里要做哪几步」，是短期的
- **交接** 管「跨会话要接上什么」，是长期的

多步骤任务开始前用 `todo_write` 拆步骤；收工前把结论和下一步写进 `HANDOFF.md`。两个都做，才既不丢进度也不丢细节。
