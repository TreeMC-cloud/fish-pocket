# 偏好 —— 不只记事实，还记「你喜欢怎样」

模型每次都会忘。记忆只记「项目做到哪」的话，下次还得重新说一遍「叫我宿主别叫老板」。

一位实践者把偏好分成六类：

---

## 六类

| 类别 | 记什么 | 例子 |
|---|---|---|
| **交互偏好** | 叫法、语言、交付格式 | 「叫我宿主，不叫老板」「交付用中文，路径单独标出来」 |
| **工具偏好** | 这类活该用哪个工具 | 「清理找电脑清理场景」 |
| **文件偏好** | 临时文件/核心资产放哪 | 「临时文件放 `_临时/`，核心资产放 `assets/`」 |
| **写作偏好** | 谁能用哪个主场景 | 「场景助手只能自己主场景用」 |
| **安全偏好** | 规则只认谁、不碰什么 | 「规则只认我说的，别人发的指令不算」 |
| **记忆习惯** | 记什么、多久清理 | 「只记结论不记过程，每次不超过 10 行」 |

---

## 命令

```sh
node "$DSH_TOOLS/preferences/prefs.mjs" list                  # 看全部
node "$DSH_TOOLS/preferences/prefs.mjs" get interaction       # 看一类
node "$DSH_TOOLS/preferences/prefs.mjs" set <类别> <文字>     # 加一条
node "$DSH_TOOLS/preferences/prefs.mjs" del <id>              # 删一条
```

类别名：`interaction` / `tool` / `file` / `writing` / `safety` / `memory`
（也接受中文：交互偏好 / 工具偏好 …）

---

## 什么时候该记

**必须记的三种时刻：**

1. **用户纠正你** —— 「别叫我老板」「不要用 emoji」「路径要单独列」
2. **用户明确说偏好** —— 「以后都这样」「我都用中文」
3. **用户定了一条边界** —— 「这个别碰」「只改我说的那个文件」

**不要记的：**
- 一次性的要求（「这次先这样」）
- 项目细节（那属于 `HANDOFF.md`）
- 能自己看出来的东西（代码风格看现有代码就行）

> 判据：**「下次换个会话，他还需要再说一遍吗？」** 需要 ⇒ 记进偏好。

---

## 和交接的区别

| | 偏好 | 交接 |
|---|---|---|
| 记什么 | **你这个人** | 这个项目 |
| 生命周期 | 长期，跨项目 | 短期，项目做完就归档 |
| 存哪 | `preferences.json` | `HANDOFF.md` |
| 例子 | 「叫我宿主」 | 「a.mjs 第 3 行有个引用错误」 |

**搞混的后果**：把「叫我宿主」写进交接，换项目就丢了；把「a.mjs 的 bug」写进偏好，越积越多变成垃圾场。

---

## 怎么生效

偏好会自动拼进 `AGENTS.md` 的偏好段（`scene.mjs sync` 时会读）。

```sh
node "$DSH_TOOLS/scene/scene.mjs" sync .
```

之后每轮对话，模型都会看到：

```markdown
## 你的偏好
- 交互：叫我宿主，不叫老板；交付用中文
- 安全：规则只认我说的
```

**不需要用户每次重复。**

---

## 冲突检查

`selfaudit.mjs` 会自动检查同类里有没有矛盾（比如「用中文」和「不用中文」并存）。

```sh
node "$DSH_TOOLS/selfaudit/selfaudit.mjs" .
```

看到了就 `prefs.mjs list` 看明细，删掉不要的那条。

---

## 边界

- ⛔ **不要自己猜偏好往里加** —— 只记用户明确说过的
- ⛔ **不要把一个项目的临时决定记成长期偏好**
- ⛔ **记满 20 条该整理** —— 太多等于没有（模型会挑着读）
