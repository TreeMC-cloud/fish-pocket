# 换会话

文件来源：移植自 luanyujia-workbench 二-标准化规范 §6.5（换会话四步）

**会话不是越久越好。** 轮次越多，每轮都要把历史重读一遍——更贵，也更笨。

一位实践者的做法：

> 「该换会话就换会话，用一次干净的开始，把模型的聪明劲拉回来。**引擎的自动压缩是安全网，不是我的主策略。**」

---

## 什么时候该换

| 信号 | 换 |
|---|---|
| 轮次超过 40 | ✅ |
| 累计 token 超过 20 万 | ✅ |
| 连续干了 3 小时 | ✅ |
| 上下文到压缩线（还没报错） | ❌ **先别换**，引擎会自己压 |
| 上下文报 413 且压缩后仍 413 | ✅ 真死局 |
| 一个话题做完了 | ✅ 建议换 |

自动守卫（`auto-guard` 插件）会在前三条触发时提醒你。

---

## 换之前必须做的：写交接

**这是唯一不能省的一步。** 换会话 = 旧上下文消失，没落盘的进度就没了。

```sh
node "$DSH_TOOLS/handoff/handoff.mjs" check .
```

不通过就不要换。`HANDOFF.md` 必须有：
- 上次做到哪（带证据）
- 当前在做什么
- **下一步的具体动作**（写不出下一步 = 这轮白干）
- 卡在哪

---

## 完整的换会话流程

### 1. 写交接

```sh
# 如果还没有 HANDOFF.md
node "$DSH_TOOLS/handoff/handoff.mjs" init .

# 填完之后检查
node "$DSH_TOOLS/handoff/handoff.mjs" check .
```

### 2. 跑闸门（三道检查一起）

```sh
sh "$DSH_TOOLS/handoff/preflight.sh" .
```

它按顺序检查：轮次是否到线 → 交接是否合格 → 有没有派单没回执。

**退出码 1 = 不能换**（通常是交接不合格）。

### 3. 告诉用户怎么做

**你没法自己开新会话**——那是用户的操作。要明确说：

> 交接已写好，可以换会话了。点左上角的「＋」新建一个，或者在侧边栏里开新的。旧会话会自动留在列表里。

### 3.5 旧交接自动进归档

`preflight.sh` 的第 4 步会**自动**把当前 `HANDOFF.md` 存一份进归档层（只进不改）。

你不需要单独做。想手动归档或回溯：

```sh
node "$DSH_TOOLS/handoff/archive.mjs" list            # 看归档
node "$DSH_TOOLS/handoff/archive.mjs" restore <名字>   # 取回
```

**为什么归档：** 换会话时旧交接不能删——那是证据。但也不能留在入口（没人读）。所以搬走不删。

### 4. 换完之后

新会话开场会读 `.scene.json` 和 `HANDOFF.md`，自动接上进度。**如果没接上，说明交接写得不够具体。**

## 别做的事

| ❌ | 为什么 |
|---|---|
| 等上下文报错才换 | 那时候已经花了冤枉钱 |
| 不写交接就换 | 进度直接丢，而且没人会发现 |
| 换完不复述当前状态 | 用户不知道新会话是不是接上了 |
| 每个小任务都换 | 换会话本身也有成本（重建上下文） |

---

## 和 auto-guard 的关系

`auto-guard` 插件在 `turn/start` 时自动记轮次，超线时提醒。**你不需要自己记账。**

提醒出现时，你该做的只有一件事：**写交接，然后让用户换。**

```sh
node "$DSH_TOOLS/handoff/handoff.mjs" check .
```

---

## 一个容易漏的点

换了会话之后，**场景身份要重新注入**：

```sh
node "$DSH_TOOLS/scene/scene.mjs" sync .
```

否则新会话不知道自己在哪个场景。这个动作应该在写交接之后、开新会话之前做。
