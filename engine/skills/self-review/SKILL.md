# 交付前自查

**核心原则：退出码 0 ≠ 能用；日志看着对 ≠ 跑通了；文件写了 ≠ 文件对了。**

这套判据来自一个真实教训：图片处理"4/4 步骤全绿、退出码全 0"，产物目录却是空的（shell 循环掩盖了 command not found）。所以自查要问的不是"我跑成功了吗"，而是"产物真的存在、真的对吗"。

## 七条硬检查（按发现 bug 的频率排序）

### I1 引用闭合 —— 最常翻车

所有本地引用必须指向真实存在的资源。写完代码逐个验证：

```
import/require 的路径 → 文件存在吗？
src=/href=/link 引用的资源 → 文件存在吗？
配置里写的入口文件 → 存在吗？
```

**iOS 上特别容易错**：`bash` 是 JS 解释器，`node` 跑在 worker 线程里，路径解析和桌面不同。用 `ls` 实际确认，别凭想象。

### I2 声明一致 —— 第二常翻车

**声明的必须真存在，调用的必须真被导出。**

```
导出了 createBookmark() → 函数真在吗？
调用了 api.sendJson() → api 里真有这个导出吗？
```

真实事故：`app.mjs` 调 `api.createBookmark(...)`，而 `api` 根本没这个导出；`api.handleRequest(method,ctx)` 和 `store(req,res)` 同名同参数数但语义相反，错误被 catch 吞成 400。**每多一条模块边界，就多一个写错契约的位置。**

### I3 语言自洽

单文件内的语言特征不能矛盾。`html_content = r'''<!DOCTYPE` 这种，开头像 HTML 但整体是 Python 脚本——不能当 HTML 存成 .html，也不能当 JS 跑。

### I4 结构平衡

括号、引号、块结构必须闭合。改完代码特别是大段替换后，跑一次结构检查。

### I5 路径合法

路径段里不能出现文件内容片段或非法字符。真实事故：用正则切函数边界时吞掉 5054 字节，`ast.parse` 仍通过、`def` 数量 65=65——检查全给了假的安全感。**改 Python 源码定位函数边界，必须用 `ast`，不能用正则。**

### I6 入口可达

声明的入口存在且能启动。服务型产物还要检查**绑定地址**：

- 绑 `127.0.0.1` → 只有本机能访问，用户部署到服务器后外网打不开
- 服务型产物应该绑 `0.0.0.0`，但自检探活仍走 `127.0.0.1`

**「能跑」≠「能用」。**

### I7 无静默失败

`catch` 吞掉错误、错误没有日志——这类代码在自查时必须揪出来。真实事故：`try { res.destroy() } catch {}` 看起来是合理兜底，实际把真实错误藏了。

## 用工具查（比手看可靠）

有两个脚本可以跑，路径用 `$DSH_TOOLS` 拼（脚本在 app bundle 里，不在你的工作目录）：

```sh
# 结构、引用、导出符号
node "$DSH_TOOLS/self-review/selfcheck.mjs" --dir <目录>

# 产物真伪：存在？是这次生成的？非空？格式能解析？
node "$DSH_TOOLS/self-review/verify.mjs" <产物路径> --since 300
```

**`verify.mjs` 治的是最隐蔽的一种假成功**：退出码 0、日志全绿、目录却是空的（或者里面是上一次的旧产物）。它同时查三件事 —— 文件真的在、mtime 是刚才、内容能解析。

两个脚本都 `exit 1` 表示有问题，输出差异集合，不是只给 0/1。

## 三步自查法

交付前按这个顺序走，每步都要有**看得见的证据**：

### 1. 产物真实性

```sh
# 不能只看退出码，要确认产物真的在、真的是这次生成的
ls -la <产物路径>
stat -c '%y %s' <产物路径>     # 时间戳是刚才吗？大小合理吗？
```

**递归找**，别只看一层目录。产物在子目录里而你在父目录 `ls`，会误报"什么都没有"。

### 2. 内容正确性

```sh
# 文件非空？
wc -c <产物>
# JSON 能解析？
node -e "JSON.parse(require('fs').readFileSync('<file>','utf8'))"
# HTML 有闭合？
grep -c '</html>' <产物>
```

### 3. 真的能跑

- **网页**：起服务，用 curl 真的请求一次，看状态码和返回内容
- **脚本**：用真实输入跑一遍，看输出而不只是退出码
- **数据文件**：能被目标程序解析

## 报告格式

自查完，向用户报告时**给证据，不要给结论**：

| 差 | 好 |
|---|---|
| "做好了" | "生成了 3 个文件，index.html 4.2KB，起服务后 curl 返回 200，返回的 HTML 里有 `<title>记账</title>`" |
| "验收通过" | "产物在 /path/，mtime 是刚才，JSON 能解析出 12 条记录" |
| "应该没问题" | "I1 引用闭合：3 个引用全部存在。I2：调用的 5 个符号都有导出。" |

## 什么时候可以跳过

改一个注释、调整文案、加一行日志——这些不用走全流程。但只要涉及：新建文件、改多个文件、生成项目、用户说"要能直接用"，就必须走。

## 拿不准时

如果你判断不了产物对不对，**说"我不确定，需要你确认 X"比说"做好了"好一百倍**。假的安全感比明确的未知更伤人。
