# 场景地盘与仲裁

文件来源：来源：移植自 luanyujia-workbench 三-跨场景协作 §一/§三

状态：活

> 两个问题：**这个场景能碰什么？**（地盘表）· **两个场景抢同一件事听谁的？**（仲裁表）

---

## 一、地盘表

每个场景必须写清四件事，缺一个就会出问题：

| 字段 | 回答什么 | 缺了会怎样 |
|---|---|---|
| **职能** | 让什么不出问题 | 不知道自己该干什么 |
| **地盘** | 具体到路径，我拥有哪些 | 和别人抢文件 / 该改的不敢改 |
| **不该碰** | 明确禁止的路径和操作 | 越界改坏别人的东西 |
| **写回点** | 记忆写到哪里 | 记忆散落各处，找不到 |

### 我们的场景（示例）

| 场景 | 职能 | 地盘 | 不该碰 | 写回点 |
|---|---|---|---|---|
| **程序开发** | 代码能跑、能构建、不引入回归 | `app/` · `engine/` · `scripts/` · `server/` | ⛔ 不改运行时的用户数据<br>⛔ 不碰 `$DSH_HOME` 里的记忆文件 | `HANDOFF.md` + `IDENTITY.md` |
| **服务器运维** | 工作台可用、端口通、部署不中断 | `/opt/wb/` · 服务器的 systemd 单元 | ⛔ 不改 App 源码<br>⛔ 不动别人的容器 | 远程工作台的任务台账 |
| **写作** | 交付物能直接发出去 | `docs/` · 指定的输出目录 | ⛔ 不碰代码<br>⛔ 不改偏好设定 | `HANDOFF.md` |
| **股票盯盘** | 数据准、记录全、结论可追溯 | 自己的数据目录 | ⛔ 不碰开发代码<br>⛔ 不改别的场景的记忆 | 场景私有记忆 |

### `.scene.json` 的完整格式

```json
{
  "name": "程序开发",
  "duty": ["代码能跑", "能构建", "不引入回归"],
  "territory": [
    "app/",
    "engine/",
    "scripts/",
    "server/"
  ],
  "avoid": [
    "不改运行时的用户数据",
    "不碰 $DSH_HOME 里的记忆文件"
  ],
  "writeback": "HANDOFF.md",
  "skill": "self-review"
}
```

**`territory` 是新加的字段**——之前只有 `duty` 和 `avoid`，缺了「我能碰哪些路径」这一层。

## 二、重叠仲裁表

两个场景都想改同一个文件时，**必须有一条判据说听谁的**，否则就是先动手的人赢，最后谁都不知道该信哪个版本。

### 仲裁优先顺序

```
1. 更具体的路径优先
     引擎/技能/xxx/SKILL.md  比  引擎/  更具体

2. 资产归属优先
     谁的工具、谁的目录，就是谁的

3. 都没写 → 先登记再动手
     ⛔ 不许先斩后奏
```

### 仲裁表（我们版）

| 撞车的地方 | 听谁的 | 依据 |
|---|---|---|
| `app/`（SwiftUI 界面） | **程序开发** | 界面归开发，运维不改代码 |
| `engine/`（引擎、技能、插件） | **程序开发** | 引擎是开发资产 |
| `engine/skills/<某技能>/` | **谁的场景谁维护** | 技能是"越用越准"的地方 |
| `docs/` | **写作** | 文档归写作，开发只提需求 |
| `$DSH_HOME/`（记忆、偏好、待办） | **各场景写自己的** | 记忆分场景，不互相覆盖 |
| `/opt/wb/`（服务器） | **服务器运维** | 部署产物归运维 |
| **清理类**（任何目录） | **运维**；别人只提请求 | 谁管清理谁把关 |
| **设计/图片类** | **写作**；别人只提请求 | 统一收口，避免风格散 |
| **都没写的路径** | ⛔ **先登记再动手** | 见下方"三" |
| **两张卡都写了** | 看谁的路径更具体 | 分层原则 |

### 怎么"提请求"而不是直接改

跨场景改别人的地盘，走这条路：

```sh
node "$DSH_TOOLS/shared/shared.mjs" notice "请求：改 docs/ 里的 XX 章节，理由是 YY" --go
```

对方看到通知后决定做不做。**不要直接动手改。**

## 三、遇到没写过的情况

**如果一件事两张卡都没写，怎么办？**

```
1. 先在自己的 IDENTITY.md 的「边界」段末尾加一行登记
2. 再动手
3. 做完在通知板说一声，让其他场景知道
```

**⛔ 不许先斩后奏。**

**为什么这么严**：他原话——

> 「**都没写的** → ⛔ **先在定位卡 §六 登记一行再动手**；**先登记后动手，不许先斩后奏**」

不登记直接干，下次另一个场景看到这个改动会以为是别人改错了，然后又改回去，来回打架。

## 四、怎么检查这两张表

### 地盘表完整性

```sh
node "$DSH_TOOLS/selfaudit/selfaudit.mjs" .
```

R5 会检查 `.scene.json` 有没有 `duty` 和 `avoid`，缺了就报错：

```
✗ [R5] 场景配置  缺字段：avoid
     → 尤其 avoid 不能空——说不清「不碰什么」就等于没有边界。
```

### 仲裁冲突检测

**已实现**（R9）。`selfaudit.mjs` 会读当前目录和兄弟目录的 `.scene.json`，两两比对 territory：

```
✗ [R9] 地盘重叠  1 处重叠：程序开发(engine/) 与 服务器运维(engine/boot.mjs)
     → 按 docs/场景地盘与仲裁.md 的仲裁表确认听谁的，或者把地盘收窄到不重叠
```

判据：**一个路径是另一个的前缀（含相等）就算重叠**。比如 `engine/` 与 `engine/boot.mjs`、`docs/` 与 `docs/`。

实测：
| 场景 | 结果 |
|---|---|
| 两个场景地盘重叠 | ✗ 退出码 1 |
| 无重叠 | ✓ 退出码 0 |

## 五、和他的差别

| | 他 | 我们 |
|---|---|---|
| 地盘表 | ✅ 9 个场景，路径级 | ⚠️ 刚加 `territory` 字段，还没填满 |
| 仲裁表 | ✅ 20 行 | ✅ 已有 10 行 |
