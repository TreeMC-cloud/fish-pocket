## 这套文档的约定

### 每条规矩必须能回答五个问题

```
① 违规长什么样？          （可判定的现象）
② 谁在判？                （唯一出处）
③ 不通过时输出什么？      （差异集合，不是 0/1）
④ 怎么证明它真的会报？    （反例）
⑤ 多久跑一次？失败进哪？  （节奏 + 去向）
```

**五条答不全的，还停在「口号」阶段**，不算规矩。

### 文档只写三类内容

| 类型 | 例子 |
|---|---|
| **怎么做** | 「加技能的步骤：1. 建目录 2. 写 front-matter 3. 登记索引」 |
| **什么算错** | 「SKILL.md 超过 12KB 算错，要拆子技能」 |
| **为什么这样** | 「因为上次压到 8KB 时删了判据，结果功能静默丢失」 |

**不写**：介绍性废话、励志语句、重复的内容。

### 文档生命周期

```
新增 → 四词状态 → 到期处置 → 复核
```

四个状态词：**现行 / 待定 / 废弃 / 归档**

- **现行**：在用，别删
- **待定**：写了但还没验证
- **废弃**：不用了，但留着看历史
- **归档**：搬走了，这里只留指针

## 和代码的关系

| | 文档 | 代码 |
|---|---|---|
| 放哪 | `docs/` | `engine/` `app/` |
| 谁能改 | 任何人都能提，但要注意冲突 | 按模块归属 |
| 进包吗 | **不进**（只在仓库里） | 进 |

**运行时工具在 `engine/skills/`，它们的规则写在 [engine/skills/_CONVENTIONS.md](../engine/skills/_CONVENTIONS.md)。**
